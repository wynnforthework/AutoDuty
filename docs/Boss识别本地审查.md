# Boss 识别本地审查（0.0.0.407）

## 审查依据

上游 PR #652 的反馈指出：按名称寻找 Boss 是补丁自身引入的依赖。对比上游 0.0.0.399（`ee4eced8`）与 PR 提交 `9f3f13a5`，原版 `GetBossObject` 按附近对象、NPC Rank（1/2/6）或 BossMod DataId 模块识别，并不使用步骤 Note。

PR 及本地后续代码却从 Note 查 BNpcName，再按名称筛选对象；有名称但匹配不到时不回退 Rank/模块。这是新增失败路径，不能把相应本地化名称问题直接归因于原版。此前名称字符串测试没有覆盖真实对象选择与游戏服务，不构成修复有效的证据。

## 本次本地修正

- 删除 Note → BNpcName → 对象名称的查找链。Boss 选择不接收对象名称或脚本名称。
- 通过 Rank/BossMod 识别对象，保留已有的范围和楼层约束；已确认的 EntityId + BaseId 可用于重新获取同一对象，避免其后 Rank 变化导致丢失。
- 先过滤死亡、不可选中对象，再选最近的有效对象；最近尸体不会挡住后方存活 Boss。
- 提前观察死亡证据时，将存活对象归属到最近的 Boss 路线位置，防止同一个对象被附近所有 Boss 步骤记为已完成。未观察过的尸体不能仅凭 Note 或附近位置证明该步骤完成。
- 保留此前 `EnsureDutyContext` 修复：对象查询独立执行，临时上下文缺失时恢复存储。接近阶段也恢复上下文，而非向空上下文做条件赋值。
- 保留对象死亡/目标完成的遭遇证据、未确认时暂停、死亡/新副本清理等机制。本次没有把离开战斗或对象消失直接等同于击杀。

名称仍可用于显示、日志，以及将**从已识别活对象读到的本地名称**关联到完成的副本目标文字。这不是按名称寻找对象；如果未观察到对象，不再使用脚本 Note 推断目标已完成。此辅助关联仍有文本/同名歧义，不是所有机制的通用完成证明。

## 验证和边界

新增回归测试调用生产环境实际使用的泛型选择器，覆盖 Rank、BossMod、已跟踪 ID、近处尸体/远处活 Boss、同名小怪、不同楼层、不可选中对象及多个路线步骤的归属。测试的 Rank/模块标志是输入数据，不能证明实际客户端的 Rank 或 BossMod 返回值正确。

保留并运行现有 Boss 遭遇、上下文、死亡、消失、阶段切换、回到入口与新副本测试。Release 编译和 33 组离线测试通过；没有进行游戏实测。本次没有发布、更新或重新打开上游 PR。

限制：Rank 和模块都不可用且未观察过的 Boss 仍无法确认；完全错过活体和尸体的中途接管不保证可恢复；多 Boss 同区域、相同/零路线位置等情况仍需实机核验。不会以新增名称兜底掩盖这些缺失证据。此前所有 boss-timeout 的原始根因并未因此全部查明。

接口证据为现有本机 API 15 的 `IGameObject.EntityId`、`BaseId`、`Position`，以及 `IBattleChara` 的 HP/死亡/可选中属性，来源是 Hooks/dev/Dalamud.xml 与现有编译引用。没有新增 Hook 或 IPC。
