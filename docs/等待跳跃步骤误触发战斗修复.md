# 等待与跳跃步骤误触发战斗（0.0.0.399.2）

截图路线为 0 StopForCombat false → 1 MoveTo → 2 Jump → 3 WaitFor IsReady → 4 Wait 200 → 5 Wait 500 → 6 MoveTo true → 7 StopForCombat true。

此前 RouteMovementPolicy 除 MoveTo 和 StopForCombat false 外默认停止战斗，导致普通等待、就绪检查和跳跃也成为战斗检查点。进入这些步骤时会重新启用 BossMod 战斗移动；Wait 还会在计时前后等待脱战，因而拉怪路线被提前打断。第 6 步 MoveTo 的 true 仅控制网格寻路，本身不表示开启战斗等待；截图无法证明该步骤运行时实际收到何种外部控制。

修正 Wait、WaitFor、Jump、JumpTo、AutoMoveFor、注释的策略，不因接战而进入战斗等待，也不在动作阶段开启 BossMod 移动。MoveTo 继续独立关闭战斗移动和输出，StopForCombat true、Boss 等保留原有战斗行为。Wait 只执行指定计时；WaitFor OOC / Combat 仍按显式条件等待。Wait 200/500 和 Jump 200 的原定短暂停留仍存在，不应理解成删去所有暂停。

回归测试覆盖截图中 0～7 的策略顺序，检查只有第 7 步可进入战斗等待和动作阶段战斗移动，同时验证显式 OOC 条件不会开启移动。Release 编译零错误，33 组离线测试通过，未进行游戏实测。未新增 Dalamud API 或 IPC，沿用既有 SetMovement 接口；不修改原始路线文件。
