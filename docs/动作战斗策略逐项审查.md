# 动作战斗策略逐项审查（0.0.0.399.3）

审查日期：2026-11-20。范围是 ActionsManager 的构建动作目录、额外公开的 PathAction 动作入口、内部任务、StageReadingPath / Moving / Action 的控制权切换。这里的“自动停战斗”指 AutoDuty 因接战中断路线并交给 BossMod 战斗移动，不指动作本身到达坐标、等待计时或点击界面所需的正常停留。

## 来源和结论

此前个人修改新增的 RouteMovementPolicy 使用“其它动作一律停止战斗”的默认值，这是本地引入的回归。0.0.0.399.2 只排除了等待与跳跃，不完整。本次移除默认开启战斗，仅 Boss、KillInRange、StopForCombat true 明确使用战斗检查点；新动作未知时不自动开启战斗，测试要求构建目录和公开动作均有审查条目。

以下“否”同时适用于前往步骤坐标时的隐式战斗中断和进入 Action 时的隐式 BossMod 移动。动作显式发出的指令仍按参数执行。到达一个动作的坐标后正常停止路线导航，是原有动作执行流程，不等于提前等待杀完怪。

| 动作 | 自动停战斗 | 内部行为、等待与边界 |
| --- | --- | --- |

| TeleportTo | 否 | 停导航、关闭自动前进，再设置位置；不隐式清怪。 |

## 内部任务修正与保留项

- 通用 Wait(int) 不再读取全局 StopForCombat 决定是否等脱战；只有 StopForCombat true 调用时明确传 waitForCombat: true。Boss 战利品与宝箱的短等待不会偷偷等待脱战。
- Interactable 去掉“接战时清空任务、排入脱战等待、重新交互”的分支；交互尾部不再无条件 SetMovement(true)。下一步骤自行申请控制权。
- 显式等待仍保留：WaitFor OOC / Combat、BLULoad 的非战斗/非施法、ForceAttack 的进入战斗。它们与“自动清怪”区分。
- DutySpecificCode 实际分支包括魔导城的骑乘/战斗回调、沙斯塔夏的选色交互、六根山的交互和攻击标记、塞尔法特尔的机关交互、Merchant's Tale 的血量/输出/预设控制。未改写这些副本机制；其中已有显式控制不属于默认策略，仍需对应副本实测。
- MoveTo 之外的自动输出策略沿用既有实现；本次不把所有非战斗动作的输出一概关闭。独立插件手动开启的 AI、施法停步、游戏强制位移也不由这个策略全部消除。
- 不批量修改原始脚本。原先依靠 Target、交互等动作隐式清怪的路线，需显式添加 StopForCombat true 或 KillInRange；本次不能保证这些旧路线无需调整。

## 验证

Release 编译零错误；34 组离线测试通过，包括新增目录审查测试：扫描实际构建目录和公开 PathAction 入口，验证每个动作已登记，测试不同参数下只有三个明确战斗动作允许中断路线，并验证未知动作默认不申请战斗控制。保留截图 0～7 顺序回归。

离线测试直接覆盖生产策略函数，未初始化游戏服务，不能证明实际 IPC、NPC 交互和全部副本机制有效。本版本尚未游戏实测。没有新增 Dalamud API 或 IPC：沿用 ActionsManager、RouteMovementPolicy 和现有 BossMod_IPCSubscriber.SetMovement(bool, bool) 调用链；默认策略修正不改变该接口签名。
