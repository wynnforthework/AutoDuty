# 创造环境极北造物院第 3 步跳跃落地误判（0.0.0.399.10）

## 现象与证据

实机在第 2 步 `Jump|-9.04, 511.70, 238.06|200` 后进入第 3 步 `WaitFor|0,0,0|IsReady`，立即暂停并报告：

`transition-unconfirmed (forced-displacement: unexpected displacement; old navigation cancelled)`

诊断 `navigation-20261119-232811-671.jsonl` 显示，步骤已经从 2 推进到 3，但角色仍在跳跃后的下落过程。位置从 `(-12.01, 504.70, 228.60)` 变为 `(-12.25, 502.34, 227.84)`，旧的逐帧高度速度阈值把正常下落识别成未知强制位移。此时 vnavmesh `pathfinding=false, running=false, waypoints=0`，第 3 步坐标为零，实际没有旧导航需要取消。

## 根因

未知位移监视器存在两个归属错误：

1. 位移速度样本跨步骤保留，上一步发起的运动可能归到下一步。
2. 监视器对所有 `Moving/Reading_Path/Action` 阶段运行，包括自身制造位移的 `Jump`，以及没有坐标和活动路径的状态等待。

因此这不是脚本缺少目的地区域，也不是第 3 步 `IsReady` 失败。要求用户给普通跳跃配置 `destination region` 会掩盖执行器错误。

## 修复

- 位移采样绑定步骤编号；步骤切换时先清空旧速度样本，禁止跨步骤归因。
- `Jump`、`JumpTo` 和 `TeleportTo` 属于脚本主动发起的普通位移，默认不推断未知区域转换。若动作显式配置 `Transition`，仍按声明的目的地区域验证。
- 零坐标动作在没有活动 vnavmesh 寻路或路径时不运行未知位移检测，因为不存在会继续追逐旧坐标的导航。若仍有活动路径，则继续执行保护性检测。
- 录制器保持一个独立、连续的位移采样流，不套用执行步骤编号。

修复没有增加新的距离、高度、速度或等待时间常量，也没有降低真正领地切换、带坐标移动、交互转换和显式转换区域的验证要求。

## 验证

Release 编译零错误，36 组离线测试通过。新增回归覆盖：跨步骤样本失效、零坐标就绪等待不继承跳跃落地、活动旧导航仍受保护、脚本跳跃默认不作为未知转换、显式跳跃转换仍参与验证。

尚需在游戏中重跑该路线确认第 2 步跳跃后第 3 步正常等待并继续到第 4 步；文件部署成功不能代替实机结果。
