# 区域转换判定与录制（0.0.0.405）

## 运行行为

转换不再仅以固定延时作为成功依据。加载标记、地图变化和异常高速位移用于发现转换；当前步骤拥有的交互、接近触发点的移动以及脚本目的区域用于判断归属。发现转换后停止旧导航并取消旧步骤任务，避免落地后继续追逐原区域坐标。

配置了目的区域时，必须同时满足地图 ID、水平范围、高度范围、角色恢复就绪，以及默认启用的附近地面检查和连续位置稳定检查，才完成当前步骤。默认稳定窗口为 1000ms；60 秒超时只会暂停，不会当作成功。未能归属到当前步骤的异常位移会取消导航并暂停；确认回到路线入口时沿用从头执行逻辑。死亡和返回沿用专门的恢复流程。

vnavmesh 没有直接提供区域切换完成事件或区域编号。当前使用已有 `Query.Mesh.PointOnFloor` IPC 查询落地点附近地面，检查网格就绪与地面高度；这不是到下一目标的可达性证明，尚未加入异步路径连通性探测。依据为本机 ECommons vnavmesh 包装以及 Dalamud 的 `IClientState.TerritoryType`、`IGameObject.Position` 和 Condition 加载状态。

## 脚本与编辑

MoveTo、Interactable 步骤编辑窗口新增“区域转换”配置。起点仍是步骤原坐标；目的区域中心应填写转换后的落点，可落地后使用“使用当前位置”。默认半径 15m、高度容差 3m，可填写目的地图 ID（0 表示不限）。电梯或移动平台可按实际机制关闭位置静止要求；网格无法覆盖的平台可以关闭附近地面要求，需要实际验证后使用。

文件格式更新为 schema 3，仍可读 schema 1、2；共享和保存会携带 `Transition` 字段。原始脚本仍须创建副本后编辑。旧脚本不批量修改：既有 MoveTo → WaitFor IsReady → 非零位置步骤可以推断目的高度与较宽的水平范围；旧交互加载保持兼容。普通水平移动、慢速电梯等无法仅靠位移阈值可靠识别，应显式标记目的区域。

## 录制

录制会尝试识别非战斗中的加载和强制位移，等待恢复就绪、位置稳定后添加转换草稿。人工标记可在机制触发前点“标记转换起点”，落地恢复操作后点“标记转换终点”。撤回可以取消未完成的人工标记。简化不会移除带转换信息的步骤。

自动识别只是候选，需检查触发点、目的范围和动作类型；跨地图录制目前仍停止并要求分别录制，手工编辑可以保存目的地图信息。未结束的人工标记不能直接保存。

## 验证与排查

离线覆盖不同楼层、不同地图相同坐标、高帧率弹射、普通行走、落地偏移、加载/角色失去就绪、地面缺失、稳定窗口重置、移动平台例外、文件往返、非法配置、编辑复制和简化保护。

游戏内仍需验证：创造环境第 36/41 步弹射、交互传送、普通加载、自由落体、死亡返回、移动平台。查看 navigation-diagnostics 中的 `transferDestination`、`transferWaiting`、`transfer-timeout-evidence`；超时原因区分等待目的区域、角色加载、地面网格、位置稳定。不同电脑按实际状态等待，稳定窗口不能替代到达证据。
