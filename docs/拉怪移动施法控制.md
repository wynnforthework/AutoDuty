# 每步独立的移动与输出控制（0.0.0.402）

本版替代 401 的持续开关语义。StopForCombat 参数仅控制当前步骤，下一步根据自身动作重新决定控制策略，不修改原脚本文件。

| 当前步骤 | vnavmesh | BossMod 战斗移动 | 自动输出 |
| --- | --- | --- | --- |
| MoveTo | 持续前往目标，不因接战停步 | 关闭 | 关闭 |
| StopForCombat false | 持续前往本步目标，不因接战停步 | 关闭 | 开启 |
| StopForCombat true | 接战时停止路线导航 | 接战时开启 | 开启 |

MoveTo 的 true/false 参数仍只表示是否使用网格寻路，与战斗开关无关。其它动作恢复默认战斗策略；Interactable 仍保留交互自身的移动控制。内部 Boss/Wait/KillInRange 的控制流程保留。

策略在开始挂机及选择当前步骤时应用，覆盖步骤就绪等待、坐标接近、动作执行与暂停恢复。MoveTo 到达时不会因为仍在战斗就等待；零坐标 MoveTo 也不会在动作入口重新开启输出。离开 MoveTo 后恢复输出不受五秒节流阻塞。继续尊重自动管理输出、BossMod AI 及替代输出插件配置。

StopForCombat false 移动期间保留 BossMod NormalMovement.Cast=DropInstants 提示，减少站桩读条；其它阶段恢复 Leeway。是否遵循该提示取决于输出插件，不能把这一提示当成 RSR 行为的游戏实测结论。MoveTo 直接关闭受管理的输出插件。

接口依据沿用现有 IPC：AutoDuty/IPC/IPCSubscriber.cs 的 BossMod SetMovement 和 RSR RotationAuto/RotationStop；委托签名见 ECommons.IPC/ECommons.IPC/Subscribers/RotationSolverReborn/RotationSolverRebornIPC.cs 的 ChangeOperatingModeWithOverridesDelegate / AutodutyChangeOperatingModeWithOverridesDelegate。本轮未新增 Dalamud 服务或事件。

诊断记录当前步骤的 stepRotationEnabled、stopForCombat、pullingInstantCasts。离线测试覆盖 false → MoveTo → true → MoveTo → false、非移动阶段施法策略、直接 MoveTo 和交互控制。

游戏验收：从相关拉怪段开始，观察 MoveTo 全程只移动，StopForCombat false 边移动边输出，StopForCombat true 接战后停导航并战斗；再验证暂停恢复、重试、零坐标动作与区域切换。离线测试通过不代表以上游戏验收已完成。
