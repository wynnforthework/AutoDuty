# 战斗移动就绪回归修复：0.0.0.399

## 问题与原因

398 的统一就绪检查在 Reading_Path 和 Moving 阶段都使用 IsReadyFull。该状态包含技能 AnimationLock；战斗中施放普通技能会短暂变成 false，导致 Moving 停止 vnavmesh 路径、回到 Reading_Path 并重新等待连续一秒就绪。反复出招因此反复中断移动。代码中存在这条明确的中断链，游戏内是否还有其他来源需要实测确认。

## 修改

- 路线读取和移动阶段使用 IsReady，保留加载、过场、死亡及实际占用检查，技能动作锁不再取消路径或重置寻路就绪观察期。
- 非导航阶段保留原有完整就绪要求，不移除加载、暂停、死亡和跨区域保护。
- 进入 StopForCombat 动作时，BossMod 移动权限立即采用该步骤参数。false 不再先开启 BossMod 移动，再通过任务关闭。

## 原有脚本语义

MoveTo 的 true/false 是是否使用网格，true 使用 vnavmesh，false 直接移动。战斗是否中断路线由 DutyData.StopForCombat 决定，默认 true，前一个 StopForCombat 修改后持续生效。MoveTo 并非独立的“始终不停”动作。

StopForCombat 先移动到其坐标，再切换开关。因此需要拉怪持续移动时，先在合适位置关闭开关，再配置 MoveTo，最后在集怪位置开启。开启后，路线移动暂停，交给战斗控制；远距离敌人的既有战斗追赶寻路仍保留，不应将其与继续前往路线目标混淆。
