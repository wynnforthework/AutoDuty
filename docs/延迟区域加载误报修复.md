# 0.0.0.397：延迟区域加载误报修复

## 现场证据

2026-11-19 本地 navigation-diagnostics：

- 魔导神门巴别塔，第 24 步。09:37:38.380Z 从 (400.06, 0, -153.09) 请求移动到 (221.43, 1.06, 332.96)；09:37:38.729Z 的 BetweenAreas 回调中，角色坐标已变成 (355.23, 0, 370.70)，且 playerValid=false。deathOrReturn=false。
- 末日树海万相森国，第 9 步。前面的 AutoMoveFor 完成后跳过未启用的宝箱步骤，开始下一段 MoveTo；随后才触发区域加载。

两个案例中，下一段目标不在加载前位置的 10 米内，不符合现有“移动到附近入口触发传送”的完成证据，因此进入 unexpected-position-transition 保护分支。此前此分支立即报错暂停，用户手动重试才从加载后的新位置重发寻路。

## 修复行为

未被当前步骤认领的加载先暂停执行更新，取消旧任务及旧寻路，等待角色和加载条件连续稳定一秒。对于未失败、未手动暂停、没有死亡/Return 证据的 MoveTo，保留当前序号，从新位置重新发起当前步骤。没有把传送视为当前步骤完成，没有递增序号，没有补充失败重试预算，也不记为人工干预。已有的近距离移动传送和真实交互传送完成流程保持独立。

确认回到入口时沿用从头执行恢复；不能安全重发的动作、已失败的步骤保留暂停保护；超过 60 秒未就绪则报告失败。重复加载标志不能无限推迟期限。
