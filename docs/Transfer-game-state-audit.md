# 区域转换状态审查与游戏信号接入（0.0.0.399.8）

之前的隐含距离前提不够可靠，也未充分向用户说明。`.399.6` 的 12 米扩大方案已弃用；`.399.7` 已取消把后续步骤目标当落地区域。本次继续移除加载识别对旧目标距离、弹射识别对固定层差/位移量/两秒采样期限的依赖。

## 实际接口证据

- 官方接口源码：<https://github.com/goatcorp/Dalamud/blob/master/Dalamud/Plugin/Services/IClientState.cs>。本机 API 15 的 `Dalamud.xml` 同时确认 `ZoneInit`、`TerritoryChanged`、`MapIdChanged`、`MapId` 和 `Instance`；新增事件签名由本机 Release 构建核对。
- `ZoneInit` 表示游戏初始化区域，`TerritoryChanged` 表示领地标识变化，都不能单独当作转换完成。
- `MapIdChanged` 可能只是当前地图楼层改变，不独立触发步骤完成。事件记录并使旧地面/路径验证失效。
- `BetweenAreas` / `BetweenAreas51` 表示加载状态，`BeingMoved` 表示游戏强制移动。结束状态仍需独立验证。
- 现有 vnavmesh IPC 提供 IsReady、PointOnFloor、Pathfind；本机包装在 IPCSubscriber.cs。它们分别证明网格状态、附近地面和路径结果，没有提供覆盖所有游戏机制的统一区域转换完成接口。

## 行为调整

1. 加载事件归属到正在执行的移动，不要求接近旧目标或沿指定直线。区域初始化/领地变化也可观察转换，不依赖必须出现 BetweenAreas。非移动动作需有当前交互证据；无拥有步骤的运行中转换先停导航，再在 Framework 回调中安全暂停。
2. 无加载强制移动必须有真实 BeingMoved 信号、当前移动步骤及就绪屏障意图。移除“层差至少10米、朝后续高度移动至少6米、两秒内接近”等猜测。普通坐标异常只触发导航停止；只有作者显式配置的真实目的区域可与此异常组合验证，旧脚本不能凭异常和一条路径自动宣告成功。
3. 识别转换与确认完成分开。加载/不可操作/强制移动仍持续时不完成；恢复后检查脚下网格地面和持续稳定，旧脚本还必须验证到后续目标的异步路径及末端。转换发生后无需再人为移动超过2米才允许恢复；同坐标跨区也能成立。后续步骤依然独立寻路。
4. 信号绑定当前步骤，重置时清除；ZoneInit/MapIdChanged 在 Dispose 退订，避免热加载重复处理。诊断新增 map、instance、transferSignals，明确成功所用信号。

## 保留的边界与限制

距离/速度阈值仍用于异常检测、导航误差和数值稳定检查；短暂稳定窗口用于消抖，超时用于安全暂停。这些阈值不代表“到了几秒或几米就说明传送成功”。作者显式配置的区域边界继续有效。未将整个系统宣称为没有阈值，也未声称所有机制都能自动识别。

旧脚本的“真实强制移动信号 + 就绪意图 + 稳定地面 + 后续路径”仍是兼容推断，不能绝对区分所有击退/移动平台/传送。没有信号、没有显式落地契约的未知机制会暂停；建议通过录制或配置提供真实目的区域。MapId、领地和网格单独均不足以证明完成。当前转换超时上限仍是安全边界，极慢加载超过上限可能暂停，不会因此跳步。

Release 编译零错误，36组离线测试通过。覆盖远离旧目标的加载、长步骤、慢加载、同坐标转换、ZoneInit/领地信号归属、纯位移拒绝、真实强制移动及死亡/返回排除，并保留第18/32步真实路线回归。尚未游戏验证新增事件的触发顺序和全部机制，尤其需实测弹射是否提供 BeingMoved；缺少信号时安全暂停属于已知限制。
