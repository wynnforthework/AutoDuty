# 数理神典石换矿石（独立功能分支）

在主窗口 Main 页展开“数理神典石购买矿石 / Mathematics ore exchange”，启用购买，选择 1–4 种矿石，使用“上移”调整轮换顺序。默认关闭、默认选择上弦月矿石。配置按 AutoDuty 配置档保存；成功购买后的下次索引也保存，修改选择/顺序会重置到第一项。

挂机每次实际出本并准备完毕后检查（含最后一次出本，不依赖“Between actions”开关）。数理神典石 **严格大于 1500** 时，只购买当前一种矿石 **3 个**，单价必须 500，总价必须 1500。确认背包增加 3 个且数理减少 1500 后才推进轮换；不重复购买同一次请求。小于等于 1500 不触发。

购买完关闭商店，回到原有串行动作队列继续挂机；最后一轮执行完购买后按原设定停止，不额外加一轮副本。无需回到购买前地图即可排本。原有 Stop 按钮会中断移动/交易；未确认成功不推进索引。

## 移动和前置条件

需要已解锁图莱尤拉尔传送、幻境村入口、尔密娜和各自矿石的任务条件，vnavmesh 可用，背包有空间。从外部地区先用 AutoDuty Goto 前往图莱尤拉尔，导航至港口 (17.5, 12.2)，只与该位置唯一匹配的以太奔流交互，确认框必须包含当前客户端语言的幻境村名称。到村后导航至尔密娜 (6.9, 7.3)。支持 1269 / 1278 两种村地图；不自动做解锁任务。

地图坐标通过客户端 Map 的比例和偏移换算并投射到导航地面。NPC 使用 BaseId 1053904；商店 1770925；币种 Item 48；上弦月 46850、下弦月 50058、朔月 50977、新月 47750。物品、币种和单价必须与实际商店匹配，不按固定显示行号买。

移动总超时五分钟；打开菜单三十秒；提交交易十五秒。币种/价格不匹配、未解锁、找不到对象、无空间、未知布局或未知确认框都会停止挂机并打印错误，不跳过失败重新排本。入口确认和实际 NPC/商店流程尚需实机验证。

`dotnet run --project tests/OrePolicy.Tests.csproj` 验证严格阈值、1–4 种轮换、失败不推进、无效配置及重载索引。

```powershell

```

待实测：1500/1501 边界、1/2/4 种跨出本轮换、港口入口及任务锁、四种矿石可见性、背包满、交易中 Stop、购买后自动继续排本、最终轮购买后停止。当前不创建 PR。

## 手动实机测试

主界面展开矿石购买设置，停止挂机后可使用以下一次性按钮，不必开启自动购买：

- **前往 NPC 并打开商店（不购买）**：0 神典石也可测试，复用正式流程前往尔密娜、打开商店并核对当前轮换矿石、币种和 500 单价，随后关闭商店并停止。
- **花费 500 数理试买 1 个矿石**：至少持有 500 数理，真实购买当前轮换矿石 ×1，核对物品及扣币后停止。没有足够数理时提示且不出发。

两种测试都不修改正式购买轮换索引，不排副本，不持久化测试模式。执行中可点击“停止矿石流程”或原有 Stop。正常出本检查仍严格要求 >1500，购买 3 个；测试不能替代最终出本触发、买完继续挂机的验收。

## 实机反馈修正：图莱尤拉大水晶路线

前往图莱尤拉后改为导航至大水晶（Aetheryte 216），选择幻境村的直接传送选项或都市传送目的地（Aetheryte 239，同属传送组 14）。不再前往港口入口。先处理菜单及匹配的确认框，再考虑移动，发出传送请求后等待地图变化，不重复交互。菜单没有幻境村或无法识别时停止并记录菜单内容。

待实测：其他地图出发 → 图莱尤拉大水晶 → 幻境村 → 尔密娜；国服实际菜单文字、都市传送与确认框、尚未解锁、传送中停止。数据依据 xivapi/ffxiv-datamining 的 Aetheryte 表。

### 大水晶原地等待修正

前往城市改为直接发起 Aetheryte 216 传送，到达后不再等待 GotoHelper 的网格准备。水晶交互按水平碰撞边缘距离判断，必要时寻路至水晶外围地面，不要求走到水晶中心。菜单在通用就绪判断之前处理。聊天窗口、日志与设置面板显示当前步骤；同一步骤 30 秒未完成会停止并报告具体步骤。此更改仍需验证真实客户端的大水晶交互和菜单跳转。

### 客户端数据读取异常修正

移除 `Level.GetRow(10566589)`：导出的该引用不能作为当前客户端的 Level 行号直接解引用。改从对象表查找 `ObjectKind.Aetheryte / BaseId 216`，读取实际坐标及碰撞半径。找不到对象时显示等待步骤并在 30 秒后停止。帧回调中的托管异常记录完整类型、消息、堆栈、区域和步骤后停止流程，避免逐帧重复抛出。尚需实机验证大水晶对象识别及菜单。

### 靠近水晶超时诊断

先在传送落点尝试交互 4 秒，再按需靠近；交互不再依赖 Move 返回到达。靠近期间每 2 秒有限尝试交互，菜单出现后优先处理。网格未就绪记录等待，投影地面失败尝试落点方向的中点，仍失败立即停止并报告坐标。日志每 5 秒记录角色/水晶坐标、水平距离和半径，并记录寻路状态。原地空等的具体原因尚需以新版日志与实机行为确认，31 项独立检查不覆盖客户端网格与交互。
